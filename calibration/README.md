# calibration — 标定小车的被控对象模型

planner 的模型必须和真车一致,否则闭环性能靠运气。这里放**测量**这些常数的工具、方法和历史记录。

| 文件 | 作用 |
|---|---|
| `calib_model.py` | **被控对象模型**:PWM↔速度、偏航臂、偏航死区、端到端校验 |
| `calib_gyro.py` | **yaw 来源核对**:编码器 vs IMU 陀螺 vs 激光 ICP,判断 `/odom` 的 yaw 该信哪个 |
| `results/` | 每次标定的记录(日期、电压、结果)|

标定出来的常数写在 `mpc/mpc_baseline/config.py` 的 `RobotConfig` / `Variant1Config` 里。

---

## 核心结论:被控对象是**仿射**的,不是比例的

电机有静摩擦,PWM 要先越过一个阈值轮子才转:

```
轮速 (m/s) = (PWM − pwm_offset) / pwm_per_mps
```

**这一点如果没建模,会伪装成别的问题。** 我们最初用比例模型 `轮速 = PWM/k` 反推偏航臂,得到 0.168 / 0.125 / 0.095 —— 随 PWM 单调漂移,看起来像"几何参数错了"。把偏置算进去之后,同一批数据给出 0.199 / 0.195 / 0.186,**一个常数**。

> **判据**:如果你测出的臂长随 PWM 变化,那不是长度不对,是你漏了偏置。

同样的结构在偏航轴上又出现了一次(见下面的"偏航死区")。

## 怎么跑

```bash
roscar
python calibration/calib_model.py --test yaw       # 原地旋转,不需要空间
python calibration/calib_model.py --test linear    # 需要前方 ~1.5 m
python calibration/calib_model.py --test couple    # 定速扫偏航,看转弯是否掉速
python calibration/calib_model.py --test arc       # 端到端校验(过完整的指令链)
python calibration/calib_model.py --all --mags 30,40,60 --secs 1.5
```

参考基准是 `/odom`:xy 来自编码器(已用激光标定过尺度),yaw 来自 IMU 陀螺。Ctrl-C 或任何异常都会**硬急停**。前向测试会先检查净空,不够就跳过。

### 每个测试测什么

| 测试 | 指令 | 得到 |
|---|---|---|
| `yaw` | 左轮 −P、右轮 +P(原地转) | 有效偏航臂 `wz_arm` / `steer_arm` |
| `linear` | 四轮同为 P(直行) | `pwm_per_mps` 斜率 + `pwm_offset` 截距 |
| `couple` | 定住 v,扫 \|w\| | 转弯是否损失前进速度;偏航跟踪率 |
| `arc` | 过 `velocity_to_wheel_pwm` 的完整指令链 | 端到端指令 vs 实际 |

**至少测 3 个 PWM 档**,否则分不清"斜率错"和"有偏置"。对 v 和 w 各做线性拟合:截距 = `pwm_offset`,斜率倒数 = `pwm_per_mps`;偏航臂 = `((P−offset)/k) / w_实测`。

## 实测结果

### 平移轴(两次不同电压)

```
 9.8 V : pwm_per_mps 73.4, pwm_offset 17.0, arm 0.194     拟合残差 ±0.003 m/s
10.5 V : pwm_per_mps 72.1, pwm_offset 14.0, arm 0.198     ← 当前配置(config 的 wz_arm = 0.196)
11.1 V : pwm_per_mps 68.4, pwm_offset 13.2, arm 0.194     拟合残差 ±0.003 m/s
```

**第三个点验证了外推**:两点模型预测 v@mag40 = 0.403,11.1 V 实测 0.393(差 2.5%)。
arm 三连 0.194/0.198/0.194 —— 几何常数盖章。三点灵敏度:dk/dV ≈ −3.8,doff/dV ≈ −3.0。
详见 [`results/2026-08-04_11.1V.md`](results/2026-08-04_11.1V.md)。

斜率只差 **1.8%**、臂长差 **2%**;动得最多的是**摩擦阈值**(17→14,电压高时更低的 PWM 就能破静摩擦)。

> 臂长是**同一电压下两个轴的比值**,电压被消掉了,所以两次高度一致 —— **这是最该信的数**。
> 我们一度警告"充满电后 `pwm_per_mps` 会完全失效",实测证明是**夸张了**。

### 偏航轴:第二个死区

麦轮要偏航必须让滚子**横向刮擦**,这需要一个独立的阈值力矩 —— 逐轮的 `pwm_offset` 补不了它,因为那只保证每个轮子**自己的**转速正确。

```
指令 → 实际:  0.30→38%   0.60→67%   0.90→75%   1.20→92%
拟合: w_real = 1.079 · (w_cmd − 0.219)
```

**同样的判据**:百分比随幅值**上升**是死区特征;时间滞后会在每个幅值损失**相同比例**。

修法是 `kinematics.yaw_feedforward`(`yaw_deadband=0.219`, `yaw_gain=1.079`),并**限幅**使内侧轮不会反转 —— 低速时补偿会把内侧轮推成倒转,而那种速度下车本来就交付不了满偏航,限幅让模型诚实地承认这一点。修复后实车重测:

| \|w\| | 修复前 | 修复后 |
|---|---|---|
| 0.30 | 38% | **106%** |
| 0.60 | 67% | **102%** |
| 0.90 | 75% | **100%** |
| 1.20 | 92% | **111%** |

### 死区补偿:加常数,不要逐轮钳位

旧实现把每个轮子**独立**抬到一个固定值,这会**抹平转向差分**(差分就是全部的转向信号):mag 20 时 |w|≤0.45 实际输出 0 rad/s。

正确做法是仿射逆 `PWM = v·k + offset·sign(v)` —— 给每个轮子加**同一个**常数,轮间差值不变,`(P−offset)/k` 反解回去正好是指令值。

### v–w 耦合:**不存在**

一度以为转弯时前进速度掉到 53%。那是**度量错误** —— 算的是位移在起始航向上的**投影**,车走弧线时投影当然缩水。沿**弧长**测:

```
|w| 0.00 → 95%    0.60 → 101%    1.20 → 107%     拟合系数 −0.047(噪声)
```

`rollout_unicycle` 假设 v 与 w 无关,**这个假设是对的**。

---

## ⚠️ 三个坑

1. **yaw 必须运行中连续积分,不能用首尾差。** `/odom` 的 yaw 缠绕在 (−π, π],转过半圈读数就废了 —— 第一次跑 PWM 60 转了整整一圈多,首尾差读出 −3.4°,把臂长算成 **−7.165 m**。脚本现在每个脉冲采样 6 次累加。
2. **电池电压影响 `pwm_per_mps`(小)和 `pwm_offset`(大)。** 想要严谨就在实际使用的电量下重测;至少记下当时的电压。
3. **同一电压下测完两个轴再算臂长。** 用旧常数里的轮速去除新测的偏航率,会把电压差算进几何里。

## 电压到底影响多少?(实测回答)

**短答:跑 magnitude 40 就别管电压了。** 低幅值才需要在意。

### 闭环对速度尺度误差不敏感

两个电压点实测的灵敏度:`pwm_per_mps` **−1.86/V**(−2.6%/V),`pwm_offset` **−4.29 PWM/V**,
臂长 +0.006/V(几何量,应该 ~0,这个数就是测量噪声)。

外推到 9.5–12.0 V,模型对 magnitude 40 的速度预测会偏 **−23% 到 +23%**。
把这个失配注入仿真(planner 用出厂常数,"车"用该电压的真实常数),真实场景 15 seeds × 4:

| 电池 | 实际 v@mag40 | 模型误差 | 成功率 | 碰撞 |
|---|---|---|---|---|
| 9.5 V | 0.294 | +23% | 0.983 | 0.017 |
| 10.0 V | 0.327 | +10% | 0.983 | 0.017 |
| 10.5 V | 0.361 | 0% | 0.950 | 0.050 |
| 11.0 V | 0.395 | −9% | 0.983 | 0.017 |
| 11.5 V | 0.431 | −16% | 0.883 | 0.083 |
| 12.0 V | 0.468 | −23% | 0.950 | 0.033 |

**没有趋势** —— 波动在 n=60 的种子噪声内。3 Hz 对着实测 odom 重规划,把整个 ±23% 吸收掉了。
这本来就是闭环该干的事:**尺度误差不需要精确建模,只要每拍纠正。**

### 但低幅值时电压是主导因素

摩擦阈值是**固定的 PWM 偏置**,幅值越高它占比越小:

| magnitude | 9.5 V | 12.0 V | 极差 |
|---|---|---|---|
| 20 | 0.023 | 0.179 | **7.8×** |
| 30 | 0.158 | 0.324 | 2.1× |
| **40** | 0.294 | 0.468 | **1.6×** |
| 60 | 0.564 | 0.757 | 1.3× |

而且阈值本身在动,**能不能转向的下限跟着动**:

```
 9.5 V : 偏置 18.3 PWM -> magnitude 低于 21.8 完全不能转向
10.5 V : 偏置 14.0 PWM -> 低于 17.4
12.0 V : 偏置  7.6 PWM -> 低于 10.9
```

`build_live_cfg` 的下限检查因此**按亏电的包**算(`PWM_OFFSET_LOW_BATT_MARGIN = 4.5`),
所以它拒绝 magnitude 22 以下 —— 宁可拒绝一个满电时本来能用的配置,也不要在亏电时
放行一个转不了向的配置。

### 所以什么时候真需要重新标定

| 情况 | 要不要重测 |
|---|---|
| 电池从满到亏 | **不用**。闭环吸收得掉,只要 magnitude ≥ 30 |
| 想跑很低的 magnitude(< 25) | **要**,而且要在你实际使用的电量下测 |
| 换电机 / 轮子 / 底盘 / 地面材质 | **要**,`arm` 和偏置都会变 |
| tick log 的 `real/cmd` 持续偏离 1.00 | **要** —— 这是唯一可靠的触发信号 |

出厂常数是 10.5 V 测的。**不必为了标定去追 12 V** —— 那个精度这套闭环用不上。

## 什么时候要重测

- 换电机 / 轮子 / 底盘,或明显换了地面材质
- 长期使用后电机磨损(偏置会变)
- 发现 planner 规划的路径和实际走的差得多 —— **tick log 的 `real/cmd` 列就是干这个的**,持续偏离 1.00 就该重测
